# 問題解決アプリ 全体モック 指示書 v2

## 目的

問題解決技法アプリの**体験を最初から最後まで通せるモック**を作る。
目的は、「紙が埋まっていく」「泡で問いかける」「できなかったあとに戻れる」の3つが、実機で気持ちよく回るかを確かめること。
Claude APIとの通信はせず、問いや要約はすべてダミーデータで動かす。本番でAPIに差し替えられるよう、Claudeの役割は関数として切り出しておく。

## 前提となる考え方（迷ったらここに戻る）

このアプリには3つの核がある。

1. **問題を解くハードルを下げる**：AIは答えを出さない。問いかけて、本人が自分の言葉で書けるようにする
2. **もう一度向き合うハードルは、もっと下げる**：できなかったあとに白紙に戻さない。前の紙の上に重ねて、変えたい一点だけ変える
3. **すべての選択は本人がする**：やるか、もう一度やるか、やめるか。AIは選択肢を出すだけ。やめることも正式な選択肢

使う人は、頭が散らかって止まっている状態にいることが多い。**画面の情報量を増やさない**。演出は意味のある瞬間だけ。常に動いているものは泡だけ。

## 技術スタック

- Vite + React + TypeScript
- Motion（旧 Framer Motion）：ズーム遷移、球の発射、紙に文字が入る演出
- React Three Fiber + @react-three/drei：泡の描画（WebGL不可・動き削減時はHTMLカードに置き換え）
- Tailwind CSS
- 状態は localStorage に保存（リロードしても紙が残る）
- モバイルファースト。基準サイズは 390×844

## 画面構成（4画面）

| 画面 | 役割 |
| --- | --- |
| A. 引き出し | 過去の紙の一覧。新しい紙を始める |
| B. 紙 | 1つの問題の全体。7つの枠が埋まっていく |
| C. 作業 | 1つの枠をズームして書く。泡が漂う |
| D. 今どう？ | 通知から開く。やれたかを選び、次を決める |

---

## A. 引き出し画面

- 紙がカードとして並ぶ。新しい順
- 各カードに見えるもの：困っていること（1行）、状態、重なり枚数（2回目以降なら「2枚目」）
- 状態は4つ：書いている途中 ／ 実行待ち ／ できた ／ 置いてある
- 「置いてある」紙は一覧の下に、少し薄く。消さない
- 上部に「新しい紙」ボタン。押すと白紙のB画面へ
- **評価や達成率の表示は置かない**。数を見せるだけ

---

## B. 紙画面

### 見た目
- 1枚の紙が画面いっぱいに。縦スクロールで全体が見える
- 7つの枠が、紙の上に印刷されたように並ぶ。枠の中は最初は空
- 枠の名前は手法の用語を使わない：

| # | 枠の名前 | 中身 |
| --- | --- | --- |
| 1 | いま困っていること | 吐き出した中から選んだ問題（1行） |
| 2 | どんな場面か | 具体化した場面（Claudeが一文にまとめる） |
| 3 | 今回の目標 | 本人が書いた目標 |
| 4 | できそうなこと | 出した案のリスト |
| 5 | やってみること | 選んだ案（1つ）と、選んだ理由 |
| 6 | いつ・どこで・最初の2分 | 実行計画 |
| 7 | やってみてどうだった | 振り返り（通知後に埋まる） |

### 動き
- 空の枠のうち、**次に書く枠だけがほんの少し明るい**。急かさない
- 枠をタップすると、その枠がズームインしてC画面になる（0.3秒以内）
- 埋まった枠は、タップでC画面に戻って直せる
- C画面から戻ると、空だった枠に**文字がすっと入る**（タイプライター風、0.5秒程度）
- 7枠が埋まったら、紙の下に「この紙を閉じる」は出さない。紙はいつでも開ける

### 重なる紙（2回目以降）
- 7番で「できなかった」→「同じ案で／別の案で」を選んだ時、紙の上に**新しい紙が重なる**
- 下の紙が端から少し見える。右上に「2枚目」
- 新しい紙は白紙ではない。1〜3番は前の紙から**引き継がれた状態**で埋まっている。4番の案も残っている
- 変えたい枠だけ明るい。「同じ案で」なら6番だけ。「別の案で」なら5番と6番
- 下の紙はタップで覗ける（読むだけ）

## C. 作業画面

### 共通の構成（上から）
1. **上部**：この枠で必要な情報。1番なら何もなし。2番以降は「いま困っていること」。4番以降は「今回の目標」も。**目標はタップでその場で直せる**（直しても4番の案は消えない）
2. **中部**：これまでの入力。球が飛んでいく先。溜まったらこの領域だけスクロール
3. **下部**：泡のフィールド + 入力欄 + 「書けた」ボタン

### 泡の挙動
- 常に**3〜4個**がゆっくり漂っている。タップできる速さ（1個が画面を横切るのに8秒以上）
- 泡の中の問いは**15字以内**。HTMLで重ねて表示（3D内に文字は置かない）
- **タップ**：泡がはじけ、問いが入力欄の上に見出しとして入る。入力欄にフォーカス
- **長押しして掴む → スワイプ**：画面外へ飛ぶ。触れただけでは飛ばない。飛ばしたら画面下に「元に戻す」を4秒
- **補充**：泡が減ったら、ダミーのClaude関数が「あと何個出すか（0〜2）」を返し、その数だけ新しい泡が端からゆらゆら入ってくる。十分埋まった判定なら補充なし
- 泡に出す問いは、枠ごとに違う（下のダミーデータ参照）

### 入力と球
- 入力してエンター（または「追加」）を押すと、入力欄から**球が発射され、線を描いて中部のリストへ飛んで着地**する（0.6秒）。着地した行が短く光る
- 空欄では送れない
- 泡を選ばずに直接書ける（入力欄は常に出ている）

### 枠ごとの違い

**1番：いま困っていること**
- 中部は「頭の中にあることを、整理せずそのまま」と薄く表示。入力は複数行OK
- 泡は出ない（まだ聞くことがない）
- 「書けた」を押すと、ダミーのClaude関数が**問題候補を2〜3個**に切り出して見せる。「これは自分で変えられる」「これは今は変えられない」のラベル付き
- 本人が1つ選ぶ → 紙の1番に入ってズームアウト

**2番：どんな場面か**
- 泡の問いは**映像にする問い**（下のダミー参照）。答えるたびに中部の「場面の文章」が書き換わる（ダミーでは答えを順につなぐ）
- 中部の上に「他の人が読んで同じ場面が浮かぶか」を目安として薄く表示
- 「書けた」ボタンの代わりに**「目標を思いついた」**ボタン。押すと紙に戻り、2番が埋まり、3番が明るくなる
- 問いは1枠につき最大2回まで。それ以上は補充しない

**3番：今回の目標**
- 上部に「どんな場面か」が見えている
- 泡の問い：「それができた日、何してる？」「できたかどうか、どう分かる？」「今週できる範囲だと？」
- 1行入力。「書けた」で紙へ

**4番：できそうなこと**
- 上部に目標。**目標はタップで編集できる**。編集しても中部の案は残る
- 中部に案が溜まる。**評価・並べ替えは一切なし**。件数だけ表示
- 泡の問い：角度を変える問い。ダミーのClaude関数が「まだ出ていない角度」の問いを選んで補充する
- 「書けた」で紙へ（案が1個以上あれば押せる）

**5番：やってみること**
- 中部に4番の案が並ぶ。1つタップして選ぶ
- 選ぶと、その案の下に2つの問いが順に出る（泡ではなく固定）：「疲れている日でもできそう？」「やってみて一番心配なことは？」。答えは任意
- 「書けた」で紙へ

**6番：いつ・どこで・最初の2分**
- 3つの入力欄：いつ（日時）、どこで、最初の2分で何をするか
- 泡の問い：「最初の30秒だけなら？」「その場所に行ったら、まず何を見る？」
- 「書けた」で紙へ。この時点で紙の状態は「実行待ち」になり、**通知の予約**が入る（モックでは画面上部に「◯日◯時に聞きます」と表示し、デバッグ用に「今すぐ鳴らす」ボタンを置く）

**7番：やってみてどうだった**
- 紙からは直接開けない。D画面から埋まる

## D. 今どう？画面（通知から開く）

### 入口
- 通知文は「今、どう？」。「やった？」とは書かない
- 開くと、紙の6番の内容（いつ・どこで・最初の2分）が上部に見える

### 選択肢（1タップ、4つ）
- やった
- まだ（あとで聞いて）
- できなかった
- 今は考えたくない

### それぞれのあと

**やった**
- 紙の7番に「できた」が入る。紙全体がほんの少し明るくなる演出（1秒）。それだけ。派手にしない
- 引き出しでの状態は「できた」

**まだ（あとで聞いて）**
- 次に聞く時間を選ぶ：3時間後 ／ 明日 ／ 自分で決める
- 紙は「実行待ち」のまま

**できなかった**
1. **理由を選ぶ**（書かせない）。ダミーのClaude関数が、6番の内容に合わせた選択肢を3〜4個作る。最後に「その他（書く）」
2. 選んだら、**次を選ぶ**。3択：
   - 同じ案で、もう一度 → 新しい紙が重なり、6番だけ明るい。ダミーのClaude関数が「前より小さくするなら」を1〜2個提案（例：最初の2分 → 最初の30秒）。採用は本人
   - 別の案で → 新しい紙が重なり、5番と6番が明るい。4番の案はそのまま残っている
   - この問題は、今は置いておく → 下の「置いておく」へ
3. 理由は紙の7番に入る。責める言葉は使わない。「今回は進まなかった」

**今は考えたくない**
- 通知が止まる。紙は「実行待ち」のまま残る
- 「また聞いてほしくなったら、紙を開いてください」と1行だけ

**置いておく**
- 紙に「今は置いておきます。戻りたくなったら、いつでも」と1行入る
- 紙が引き出しの下段に移る演出（しまう）。消えない。通知は止まる
- 置いた紙はいつでも開けて、「もう一度やる」を選べる

### 「置いておく」が増えた時
- 置いてある紙が3枚以上になったら、引き出し画面の下に「誰かに相談するのも、ひとつの選択です」と相談先へのリンクを1行だけ出す。押しつけない

---

## 安全導線（モックでも入れる）

- 全画面の右上に小さな「相談先」ボタン
- 1番・2番の入力で、ダミーのClaude関数が「深刻」と判定した場合（モックでは特定のキーワードで発火）、問題解決の流れを止めて、相談窓口の画面に切り替える。その入力は紙に書かれない
- 窓口の情報はモックではプレースホルダーにし、本番で公式一覧から取ることを明記

---

## 動きを減らす設定（prefers-reduced-motion）とフォールバック

- ズームは即時切り替えに。球の発射はなし（フェードで追加）
- 泡はカード表示に。最大3枚、並んで表示。タップで選ぶ、「×」で消す
- WebGLが使えない環境でも同じカード表示に
- 紙に文字が入る演出はフェードのみ

## アクセシビリティ

- 押せるものは44×44px以上
- 泡はボタンとして扱い、問いの文をaria-labelに
- 色だけで状態を表さない（状態は文字でも書く）
- キーボードが開いても入力欄と送信ボタンが隠れない（visualViewportで高さを合わせる）

## 見た目のトーン

- 紙は少しクリーム色。罫線は薄く。手書き感は出しすぎない（読みやすさ優先）
- 泡はシャボン玉の透明感。背景は落ち着いた明るい色
- フォントはNoto Sans JPなど日本語が読みやすいもの
- 効果音は初期オフ。切り替えを設定に

## ダミーデータ（Claude関数の返り値として固定で用意）

### Claude関数の一覧（本番でAPIに差し替える）
- `splitProblems(text)` → 問題候補2〜3個（ラベル付き）
- `nextQuestions(step, context)` → 次に出す泡の問い（0〜2個）
- `summarizeScene(answers)` → 場面の一文
- `reasonOptions(plan)` → できなかった理由の選択肢
- `shrinkPlan(plan, reason)` → 縮小版の提案1〜2個
- `isSerious(text)` → 深刻判定（モックではキーワード）

### 1番：吐き出しの例と切り出し結果
入力例：
```
仕事がうまくいかない。月曜がつらい。会議で話せない。部屋も片付いてない。
```
切り出し結果：
```
・会議で話せない（自分で変えられる）
・月曜がつらい（自分で変えられる）
・部屋が片付いていない（自分で変えられる）
```

### 2番：場面を映像にする問い（この順で）
```
最近だと、いつ？
どこに座ってた？
誰がいた？
最初に何て言われた？
その時、体はどうだった？
何て答えた？
本当はどうしたかった？
```
場面の一文（最終）：
```
月曜9時の会議室で、上司に「で、どうなった？」と聞かれ、3秒黙った。本当は、要点を3つ言いたかった。
```

### 3番：目標の問い
```
それができた日、何してる？
できたかどうか、どう分かる？
今週できる範囲だと？
```
目標の例：
```
今週の月曜の会議で、要点を1つだけ言う
```

### 4番：角度を変える問い（角度ごとに1つ、まだ出ていない角度から出す）
```
人に頼むとしたら？
やらないとしたら？
道具で解決するなら？
5分でできることは？
前にうまくいった時は？
友達ならどう言う？
時間を変えるなら？
場所を変えるなら？
小さく分けるなら？
```

### 5番：固定の問い
```
疲れている日でもできそう？
やってみて一番心配なことは？
```

### 6番：計画の問い
```
最初の30秒だけなら？
その場所に行ったら、まず何を見る？
```
計画の例：
```
いつ：月曜 8:50
どこで：会議室に入る前の廊下
最初の2分：スマホのメモに要点を1つ書く
```

### D：できなかった理由（6番の例に対して）
```
会議の時間が変わった
廊下で書く余裕がなかった
書いたけど言えなかった
気力がなかった
その他
```

### D：縮小版の提案（理由「気力がなかった」に対して）
```
最初の2分を、最初の30秒に：会議の前日夜に、要点を1語だけメモする
```

### 深刻判定のキーワード（モック用。本番ではClaudeが判定）
```
消えたい、いなくなりたい、死にたい
```

## 作らないもの

- Claude APIとの通信（すべてダミー関数）
- 実際のプッシュ通知（画面内の「今すぐ鳴らす」で代用）
- 複数端末の同期、アカウント
- 共有・グループ機能

## 進め方

1. 最初に、4画面の遷移図と各画面のワイヤーフレームをテキストで提示してから着手する
2. B → C → D の順に作る。Aは最後
3. 実装後、390×844で各画面のスクリーンショットを撮って崩れがないか自分で確認する
4. iPhone実機で試せるよう、ローカルネットワークからアクセスできる起動方法をREADMEに書く
5. 「できなかった → 理由を選ぶ → 同じ案でもう一度 → 紙が重なる」の一周を、デバッグ用の「今すぐ鳴らす」ボタンで通して確認できること

## 完了条件

- [ ] 白紙の紙から始まり、7つの枠が順に埋まっていく
- [ ] 枠タップでズームイン、完了でズームアウトして文字が入る
- [ ] 1番で吐き出すと、問題候補が切り出され、1つ選べる
- [ ] 2番で泡の問いに答えると、場面の文章が育つ。「目標を思いついた」で進める
- [ ] 4番で目標をその場で直せて、案は消えない
- [ ] 泡は常に3〜4個漂い、タップで問いが入り、長押し＋スワイプで飛ばせ、4秒以内に戻せる
- [ ] 入力すると球が飛んでリストに着地する
- [ ] 6番を書くと「実行待ち」になり、「今すぐ鳴らす」でD画面が開く
- [ ] D画面で4択が選べ、「できなかった」→理由→3択が通る
- [ ] 「同じ案でもう一度」で紙が重なり、前の内容が引き継がれ、6番だけ明るい
- [ ] 「置いておく」で紙が引き出しの下段に移り、消えない
- [ ] 引き出しから過去の紙を開ける。重なり枚数が見える
- [ ] リロードしても紙が残る
- [ ] 動きを減らす設定で、泡がカードになり、ズームと球がなくなる
- [ ] 深刻キーワードで相談先画面に切り替わり、その入力は紙に残らない
